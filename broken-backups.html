The patch that broke your backups

September's Patch Tuesday broke Windows File History — the built-in backup that quietly copies your files to an external drive or a network location. Your backups may have been silently failing for a month. Here's how to check, and your three options.

The honest timeline

  • September Patch Tuesday: File History backups and restores to external drives and network locations break.
  • September 14: Microsoft ships out-of-band fix KB5129195. It does not fix File History.
  • September 22–23: the real fix ships — but only in the optional preview updates (KB5124006 / KB5124010). Optional means manual: automatic deployment policies skip preview updates entirely, so if your shop's updates run on autopilot, you never got it.
  • October 13: the fix folds into the regular Patch Tuesday bundle. Everybody gets it then.

One more wrinkle, because there always is one: the same preview KB that fixes File History (KB5124010) introduces a new bug on machines using Credential Guard — the old "the trust relationship between this workstation and the primary domain failed" error. So the manual early fix carries its own risk. There is no free move here, only trade-offs.

Who waits longest: if your machines run Windows 11 23H2 or any Windows 10 edition, the preview wave gave you nothing — you wait for October 13 no matter what. The oldest machines in the building, the ones most likely to need their backups, are the ones waiting longest for the fix. That's not commentary, that's the schedule.

Did File History silently fail on your machines? (the 2-minute check)

File History doesn't always announce that it stopped working. Here's how to check:

  1. On each machine that should be backing up: open Settings → Accounts → Windows backup (or Control Panel → File History on older builds).
  2. Look at the last successful backup date. If it says September — or if it errors when you try to run one now — it broke.
  3. Check the drive or network location it points to. If nothing new has landed there since the September updates, that's your answer.

The moral of the story: if you find a machine that hasn't backed up in weeks, that machine has been running without a net. Fix the backup before you need it.

Your options, honestly

Option A — install the preview manually (KB5124006 / KB5124010)

You get the fix now. The costs: it's hands-on per machine, auto-update policies won't do it for you, and KB5124010 can break domain trust on Credential Guard machines. Worth it if a machine's backups are critical and you can babysit the install.

Option B — wait for October 13

The fix arrives in the normal bundle, no heroics required. The cost: up to two more weeks without working File History. If you choose this, at least verify your other backups in the meantime — the external drive rotation, the cloud backup, whatever else you have. Don't assume.

Option C — both

Preview on the machines whose backups matter most, October 13 for everything else. This is what most shops with an IT person will actually do.

Whichever you pick, do the 2-minute check first. You can't make the call without knowing which machines are affected.
