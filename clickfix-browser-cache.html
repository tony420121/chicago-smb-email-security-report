The "verify you're human" button now tells your browser to hide the attack.

Microsoft is warning about an evolved ClickFix campaign: the lure is the same fake CAPTCHA shops have seen for a year — but the payload now downloads as cab.dat, hides in your browser's own cache, and loads attack code directly into memory to steal browser-stored and device credentials.

How the evolved attack works

  • The lure: a fake CAPTCHA or verification prompt telling you to paste a command into Run, Terminal, or PowerShell. Same social trick as always — "prove you're human."
  • The download: the payload arrives as cab.dat and stashes itself in the browser cache — the last place most people (and some scanners) look.
  • The execution: it runs in a hidden window. .NET assemblies load directly into memory — via csc.exe/cvtres.exe injection into timeout.exe — so there's no malicious file sitting on disk to find.
  • The target: credentials stored in the browser and on the device.
  • The staging: independent analysis traced the full chain — a command shell searching browser profile folders, a script staged in the temp folder and launched through the Windows script host, and a PowerShell staging step.

Attribution, stated plainly: this is Microsoft's warning as carried by cyberpress.org (October 2–3, 2026), independently corroborated by gbhackers with matching technical detail, plus the Threadlinqs TL-2026-2699 detection corpus. Two independent outlets saying the same thing is why this page exists.

The one rule that stops all of it: any prompt telling you to paste a command anywhere is an attack. No legitimate website, CAPTCHA, or support page will ever ask you to paste commands into Run or PowerShell. Teach every employee that one sentence.

The honest version

This is the browser-cache evolution of a ClickFix trick that's been around for a year — new hiding spot, same con. We're not claiming this is everywhere; we're saying Microsoft flagged it and a second outlet confirmed the mechanics, which clears our bar for telling you about it. If you're running Microsoft's stack, you're partially covered already — see the checks below.

What "covered" actually means here: Microsoft says Defender SmartScreen, Defender for Office 365, and Defender for Endpoint provide layered coverage, with "Possible ClickFix activity" alerts and detection as Trojan:Win32/ClickFix. Coverage is not immunity — the lure still needs a human to paste the command.

Two admin checks — turn these on

1. Turn on PowerShell script-block logging

This attack lives in PowerShell and script hosts. Script-block logging records what actually ran — without it, you're investigating blind after the fact. It's a Group Policy / Intune setting; turn it on fleet-wide.

2. Make sure cloud-delivered protection is on

Microsoft's layered coverage for this campaign depends on cloud-delivered protection being enabled in Defender. Check it — it's the difference between "Possible ClickFix activity" alerting you and silence.

And the human check, which matters more than both: if anyone on your staff has pasted a command from a website in the last month, treat that machine as compromised until proven otherwise.
