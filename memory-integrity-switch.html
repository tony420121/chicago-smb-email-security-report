October 13 flips the Memory Integrity switch — here is the 30-minute check.

Starting with the October 13 Patch Tuesday quality update, Windows begins auto-enabling Memory Integrity (HVCI) on eligible Windows 11 devices — as announced September 1. The kernel feature that can refuse incompatible drivers. Set the policy yourself, or Windows Update decides for you.

What is changing — and who is affected

Memory Integrity (also called HVCI, Hypervisor-protected Code Integrity) uses hardware virtualization to wall off kernel-mode code. Drivers that poke at memory in ways it does not allow get blocked from loading. Microsoft announced on September 1, 2026 that October quality updates begin turning it on automatically — targeting the machines that need it most: devices upgraded from Windows 10 and anything shipped with the feature off.

The driver risk, in plain English

  • Incompatible drivers get blocked. A driver written years ago that conflicts with Memory Integrity will fail to load — and in bad cases that has meant boot problems on older hardware.
  • Windows checks readiness first. Before flipping the switch it verifies the hardware floor (8th-gen Intel / Zen 2 or newer), virtualization enabled in firmware, and driver compatibility. Where Memory Integrity turns on, it brings Virtualization-Based Security (VBS) with it.
  • Manually-disabled stays off. If you deliberately turned it off through policy, Windows Update respects that and leaves it alone. But "never touched it" is not the same as "deliberately off."
  • Your early-warning log: Event Viewer → Applications and Services Logs → Microsoft → Windows → CodeIntegrity → Operational, Event ID 3087 — that is Windows flagging a driver Memory Integrity would block.

The honest best move: set the explicit Intune or Group Policy setting yourself — on or off, your call. Then the rollout enforces your decision, not Windows Update's.

Why your shop should care — the honest version

Two things keep this page honest. First: Microsoft announced this September 1, and rollout dates slip — the 26H2 watch proved that — so this page frames it as "as announced, verify your fleet's actual state," not a doomsday countdown.

Second: the affected population is specific. Secured-core fleets and clean installs already have Memory Integrity on; this page is for the upgraded-from-Windows-10 middle of the fleet, and it says so. The 30-minute check before the 13th is a device inventory plus a driver-compat pass — and then one explicit policy, set either way, so the record shows you decided.

Four actions — the 30-minute check before the 13th

1. Inventory the fleet

Which machines were upgraded from Windows 10 or shipped with Memory Integrity off? Clean installs and Secured-core are already covered — this check is for the rest.

2. Check driver compatibility

Open the CodeIntegrity Operational log and look for Event ID 3087 — Windows flagging a driver Memory Integrity would block. One bad driver found now beats one dead machine on the 14th.

3. Set the explicit policy

Intune or Group Policy: decide on or off and set it. An explicit setting is an auditable decision; “never touched it” is how Windows Update decides for you.

4. If you deliberately disabled it, confirm the policy is set

“Off because we chose off” survives the rollout. “Off because nobody ever looked” does not.
