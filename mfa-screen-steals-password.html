What if the MFA step itself is the attack?

Varonis Threat Labs disclosed TrustSink: an attacker who already controls a highly privileged Microsoft Entra account can register their own fake MFA provider inside your tenant. From then on, the "extra Microsoft login step" your employee sees is the attack — a second password prompt on a pixel-perfect Microsoft page, and the login completes with no error. Nothing looks wrong. The password is gone.

The setup — be honest about what it takes

This is a post-compromise attack, not a first break-in. It requires the attacker to already control a highly privileged Entra account — a Global Administrator or an Authentication Policy Administrator. If your admin accounts are clean and locked down, this can't start. Frame it correctly: TrustSink is what a compromised admin account enables, not something lurking behind every login. (BleepingComputer; SC Media)

What the victim sees

Your employee logs in normally: real Microsoft password page, real credentials. Then Entra redirects to the registered "external MFA provider" — which the attacker controls. That provider shows a second, pixel-accurate Microsoft password prompt. The employee re-enters the password, thinking it's part of the MFA step. The rogue provider records it — password, timestamp, source IP — then returns a valid signed token to Entra. Login completes. No error, no suspicious redirect warning, no visible interruption. (GBHackers; ThaiCERT, Sept 24, 2026)

The detail that should scare an admin

In Varonis's test tenant, every sign-in completed normally while their server collected passwords. And the kicker: resetting a captured password does not remove the rogue provider. It stays in the authentication flow and captures the replacement password at the very next login. Your incident response has to remove the rogue provider first, then reset passwords. Get that order wrong and you're just donating new passwords to the attacker. (BleepingComputer)

Five actions — do these this month

1. Audit External Authentication Methods

Open Entra and review every registered external MFA provider. Remove anything you didn't put there yourself. Varonis's own guidance: remove suspicious providers and their associated apps before resetting passwords.

2. Gate who can add one

An approval workflow for registering new MFA providers — this is a change-control item, not a helpdesk ticket. Nobody adds an authentication provider to your tenant without a written sign-off.

3. Shrink standing admin privilege

Fewer always-on Global Admins means fewer accounts that can plant a rogue provider. List your Global Admin and Authentication Policy Admin accounts, cut the standing ones to the minimum, and put the rest on just-in-time elevation where your license reaches.

4. Teach the one-prompt rule

One password prompt per login. A second one — especially one that arrives "during MFA" — is a red flag, full stop. Tell staff: "If a login asks for your password twice, stop and call."

5. Phishing-resistant MFA for every admin

FIDO2 security keys or Windows Hello for Business. This whole technique is a post-compromise play — hardened admin accounts keep it from starting.
