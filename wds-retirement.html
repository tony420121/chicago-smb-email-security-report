Microsoft just started the clock on your imaging server.

On September 21, 2026, Microsoft published support article KB5129631: Windows Deployment Services (WDS) will be deprecated starting with the next release of Windows Server. If your shop still PXE-boots machines to image them, this is the beginning of the end of that workflow — and the migration planning starts now.

What's actually being deprecated

The notice is broad. Beginning with the next Windows Server release, Microsoft plans to deprecate: the inbox WDS server role (Deployment Server and Transport Server role services); WDS-provided PXE boot and network bootstrap functionality; WDS management tools, command-line interfaces, and APIs (including WDSUTIL); WDS multicast transport and the multicast deployment workflows that depend on it; and WinPE components built specifically for WDS clients, including WinPE-WDS-Tools. (Neowin)

What "deprecated" means (and doesn't) — the honest version

No panic needed
Deprecated is not removed. Nothing breaks today: WDS keeps working on currently supported releases — Windows Server 2025 and earlier — for as long as each release remains in support. What deprecation means is: no more active development, and removal can follow in a later OS release. Microsoft framed it as early notice so shops can find their dependencies before the components are gone. (BleepingComputer)

This has been coming for years. In 2021, Microsoft deprecated Windows Setup workflows that use boot.wim from installation media in WDS mode for Windows 11 and later. Then hands-free WDS deployment scenarios were disabled by default and became unsupported for systems running Windows updates released on or after April 14, 2026. The September 2026 notice finishes the job: the whole role. (Neowin; BetaNews)

Who this hits, honestly

Most small shops don't run Server-based imaging — if you don't PXE-boot machines, this page isn't about you. But if you do: multicast imaging jobs are the most exposed. Shops using Configuration Manager are being asked to move to the ConfigMgr PXE responder without WDS — and that responder supports unicast only, so WDS-dependent multicast workflows need a new plan. Independent PXE implementations and non-Microsoft deployment products that don't depend on WDS are not affected. (Neowin; BleepingComputer)

Your migration homework — four items

1. Inventory your imaging

List every place you PXE-boot: WDS server roles, MDT/WDS task sequences, multicast jobs. You can't migrate what you haven't mapped.

2. Learn the modern path

The replacement story is modern provisioning (Autopilot/Intune) — rather than another on-prem imaging server. That's the direction Microsoft is moving endpoint setup, and the one to evaluate against your fleet.

3. Don't rebuild on WDS

Any imaging project you start today should assume WDS has an expiration date.

4. Mind the other retirements

October's theme is retirement: Office 2021 and Windows 11 24H2 lose security updates October 13, 2026 — the convergence one-pager covers that deadline. And check what your Microsoft 365 / Intune license already includes for provisioning — the Intune Suite checklist is the "what are you already paying for" version.
